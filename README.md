## Исходный текст задания

«Оконный менеджер задач»
Необходимо создать классическое настольное приложение для ведения списка дел. Главная особенность задания заключается в том, что одна и та же функциональность должна быть реализована параллельно на двух разных технологиях внутри одного решения.
**Техническое ограничение:** Использование баз данных запрещено. Весь список задач должен храниться в оперативной памяти (например, в BindingList или ObservableCollection).
Функциональные требования к приложению
Приложение должно представлять собой главное окно со списком дел и модальное диалоговое окно для добавления/редактирования задачи.
**Модель данных (TaskItem):**
Создать класс TaskItem.
Свойства: Id (Guid или int), Title (строка), IsCompleted (bool), CreatedAt (DateTime).
**Главное окно:**
Отображение списка задач. В WPF использовать ListBox с богатым DataTemplate или DataGrid.
Рядом с каждой задачей должен стоять чекбокс (или визуальный маркер), позволяющий отметить её как выполненную одним кликом.
Кнопки управления: «Добавить», «Редактировать», «Удалить выбранное».
Текстовый блок или лейбл, отображающий статистику: «Всего задач: X, Выполнено: Y».
**Диалоговое окно (Детали задачи):**
При нажатии кнопок «Добавить» или «Редактировать» должно открываться отдельное фиксированное по размеру окно (Form или Window) без ресайза.
Окно содержит поле для ввода текста задачи и две кнопки: «Сохранить» и «Отмена».
Если открывается режим редактирования, поля должны быть предзаполнены данными выбранной задачи.
**Логика удаления:**
Перед удалением задачи программа должна вывести стандартное диалоговое окно подтверждения (MessageBox.Show) с вопросом «Вы уверены, что хотите удалить задачу?». Удаление происходит только при нажатии «Да».
**Визуальная индикация:**
Выполненные задачи в общем списке должны визуально отличаться от активных (например, серый цвет текста и зачеркивание в WPF через триггеры).
Требования к реализации кода
Использовать разметку **XAML**.
Запрещено устанавливать сторонние фреймворки (MVVM Community Toolkit, Prism и т.д.).
Привязка данных (Binding) настраивается напрямую в коде-бехайнд (MainWindow\.xaml.cs).
Свойство списка задач должно реализовать уведомление об изменениях (использование ObservableCollection обязательно).
Для стилизации выполненных задач необходимо использовать Style с DataTrigger, привязанным к свойству IsCompleted.
Организационные требования
Структура проекта: Решение (Solution) должно содержать три проекта:
TodoApp.Core — Class Library. Здесь лежит единственный файл TaskItem.cs. Этот проект подключается как ссылка и к WinForms, и к WPF.
TodoApp.Wpf — WPF App (.NET Framework).
**Единообразие:** Логика работы со списком (создание объекта, проверка длины строки названия) не должна дублироваться. Если алгоритм сложный, его можно вынести в статический вспомогательный класс в проекте Core.
**Защита от сбоев:** Пользователь не должен иметь возможности нажать кнопку «Редактировать» или «Удалить», если ни одна задача в списке не выбрана. Кнопки должны быть заблокированы (Enabled = false), пока нет выделения.

## Результаты

Решение содержит три проекта на .NET Framework 4.8: TodoApp.Core, TodoApp.Wpf и TodoApp.WinForms

В общем классе TaskItem находятся свойства задачи, создание идентификатора и даты, проверка названия и уведомления об изменениях

Название содержит от 1 до 100 символов, пробелы по краям убираются

В папке решения есть отдельные файлы запуска WPF и Windows Forms и общий файл запуска обеих версий

### Задание 1

В WPF используется ListBox с DataTemplate и ObservableCollection, привязка списка настроена в MainWindow.xaml.cs

Выполненные задачи становятся серыми и зачёркнутыми через Style с DataTrigger, статистика обновляется при изменениях

### Задание 2

В Windows Forms используется DataGridView и BindingList, чекбокс меняет состояние задачи одним нажатием

В обеих версиях доступны добавление, редактирование и удаление с подтверждением, кнопки редактирования и удаления отключаются без выбранной задачи

Списки хранятся только в памяти каждого приложения и очищаются после его закрытия, базы данных и сторонние фреймворки не используются
